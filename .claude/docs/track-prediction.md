# 이동 경로 추적과 다음 목격 예측

노션 옮기기 대기 중인 임시 보관본입니다. 워크스페이스가 무료 블록 1,000개 상한에 걸려 페이지를 만들지 못했고, 자리가 생기면 `01 제품 기획` 하위 페이지로 옮기고 이 파일을 지웁니다. 문서 단일 원천은 노션입니다.

흩어진 목격 제보를 시간순으로 이어 동물의 이동 경로를 만들고, 다음 목격 가능 지역과 탐색 순서를 내는 기능입니다. 한 번의 목격을 등록하는 서비스와 갈리는 지점이고, AI 활용도 심사에 대한 답이 여기 있습니다.

## 왜 이 기능인가

게시판은 이미 포인핸드와 당근이 하고 있습니다. 다시집이 가질 수 있는 것은 게시글이 아니라 목격 데이터의 연결입니다. 사진 한 장으로 글을 대신 써 주는 것은 사람이 조금 더 시간을 쓰면 되는 일이지만, 흩어진 목격 다섯 건에서 이동 방향을 읽어 다음에 나타날 곳을 좁히는 것은 사람이 눈으로 하기 어렵습니다. 인간의 개인 지성이나 집단지성으로 추정하기 어려운 자리에만 AI를 씁니다.

## 공식

다섯 줄 전부 결정식입니다. 모델이 점수를 만들지 않고 계산된 값을 해석해 행동 문장으로 바꿉니다.

```
T1  연결 가능성 - 두 목격을 한 개체의 연속으로 볼 수 있는가
    feasible(A→B) = d(A,B) / (v_max × Δt) ≤ 1
    v_max = 소형 3.0 · 중형 4.5 · 대형 6.0 km/h

T2  경로 신뢰도 - 가장 약한 고리가 경로 전체를 결정
    track = min(match_i) × (1 − mean(d_i / (v_max × Δt_i)))

T3  방향성 - 이동생태학의 straightness index
    κ = |Σ v⃗_i| / Σ|v⃗_i|      0 = 제자리 맴돎, 1 = 한 방향 직진

T4  다음 목격 예측 - 중심은 방향으로 밀고, 원은 √t 로 퍼짐
    중심 C = P_last + κ × v_eff × h × û
    반경 r = σ × √h + ε_gps,   0.4km ≤ r ≤ 8km
    σ = 소형 0.28 · 중형 0.38 · 대형 0.50 km/√h

T5  탐색 우선순위 - 예측 원의 경계에 가까운 지점이 앞
    priority(P) = w_type / (1 + |dist(C,P) − r| / r)
    w_type = 하천·공원 1.0 · 산책로 0.9 · 학교·아파트 0.7
```

한 문장으로 줄이면 방향이 일관될수록 예측 원의 중심이 앞으로 가고, 시간이 지날수록 원이 √t 로 커집니다. 순수 확산이면 변위가 √t 에 비례하고 방향성이 있으면 선형 성분이 더해지는 랜덤워크라, 숫자 하나하나를 심사위원이 검증할 수 있습니다.

## AI가 맡는 자리

```
단계             담당              산출
체인 후보 생성    결정식 T1·T2      시간순 목격 열
같은 개체 판정    모델 + 사진 4장    photoConsistency (consistent·mixed·unclear)
원 그리기        결정식 T3·T4      중심 좌표와 반경
어디부터 찾나     모델 + Kakao POI  탐색 순서 3곳과 주의 한 줄
```

모델은 개체 동일성을 확정하지 않습니다. 품종을 단정하지 않고 점수를 다시 매기지 않으며, 프롬프트에 좌표 숫자를 넣지 않고 지역명과 방향 낱말로만 말합니다. 사진은 털색·크기·목줄이 서로 어긋나는지만 보고 같은 개체라고 말하지 않습니다.

## 데이터와 안전

새 마이그레이션 없이 `reports` 와 `match_scores` 를 읽기만 합니다. 좌표는 `coarsePoint` 즉 300m 격자로 넓힌 공개용 값만 쓰고 `exactPoint` 를 읽는 코드는 0줄입니다. 노드 좌표는 지도에 이미 낱개로 떠 있는 지점들이라 경로가 새로 드러내는 위치 정보가 없습니다.

공개된 찾는 중 신고는 관리 세션 없이 경로를 볼 수 있습니다. 어디를 찾아봐야 하는지 아는 사람이 많을수록 다시 만날 확률이 올라가고, 실종 신고는 보호자가 널리 퍼지기를 바라는 글이기 때문입니다. 숨겼거나 끝난 신고, 그리고 후보 덱과 연락 경로는 POL-03 대로 작성자 전용으로 남습니다.

## 탐색 조언

시간과 위치와 제보 밀도를 서버가 한 번에 읽어 지금 할 일 한 줄과 그 근거 한 줄로 바꿉니다. 모델이 아니라 규칙이 만드는 문장이라 화면에 AI 초안 표기를 붙이지 않고, 모델에는 규칙이 센 숫자만 넘겨 해석이 같은 사실 위에 서게 합니다.

```
기준 시각   보호자가 적은 실종 시각 하나. 후보 제보 시각은 개체가 확정되지 않아 기준으로 쓰지 않음
단계        fresh <6h · recent <24h · stale <72h · cold >=72h
행동        단계 × 동물로 고름. 고양이는 가까운 곳 반복 탐색, 개는 반경 확장
근거        반경 r km 안 발견 제보 n건(분모), 그중 닮은 후보 m건(분자)
커버리지    최근 7일 반경 3km 발견 제보 3건 미만이면 보는 눈이 적은 곳으로 보고 공유를 권함
반경 하한   격자 두 배. 300m 격자면 0.6km, 1000m 격자면 2km. 스냅 오차보다 작은 반경은 빈 문장
```

제보가 없는 것과 제보는 있는데 후보가 없는 것은 다음 행동이 다릅니다. 앞은 공유로 눈을 늘려야 하고 뒤는 지역을 옮겨야 합니다. 분모 없이 후보 수만 말하면 이 둘을 가를 수 없어 두 수를 함께 냅니다.

경계 시간 6·24·72와 커버리지 하한은 회수 데이터가 없어 정한 경험 규칙입니다. 단계가 응답에 남으므로 어떤 단계를 본 보호자가 무엇을 했는지 셀 수 있고, 그 데이터로 경계를 보정하는 것이 다음 일입니다. 제출 자료에는 데이터 기반이 아니라 규칙 기반, 보정 예정으로 적습니다.

## 함께 반영한 UX

```
할 일 → 근거 → 갈 곳   경로 카드는 세 덩이만. 지도와 타임라인이 이미 보여 주는 지역명과 시각은 되풀이하지 않음
상태 어휘       실종 · 발견 · 보호 중 · 구조 요청 · 찾음 으로 통일, 주어 없는 표기
CTA            구조 요청 → 구조·보호 요청, 내 가족 같아요 → 우리 아이인지 확인
검색 분리       발견 제보 찾기 / 실종 신고 찾기, 실종은 반려동물 이름으로도 검색
```

사용자가 알고 싶은 것은 날짜가 아니라 얼마나 오래됐는지이고, 그다음은 그래서 무엇을 하면 되는지입니다. 시간을 원시값이 아니라 맥락과 행동으로 바꿉니다.

## 남은 것

실종 신고가 없는 떠돌이 개체의 경로는 범위 밖입니다. 발견 제보끼리 배점하는 로직이 새로 필요합니다. 노출 빈도 관점에서 값어치가 있어 별도 건으로 잡는 것이 맞습니다.
